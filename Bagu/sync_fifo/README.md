# 同步 FIFO（sync_fifo）

深度 16、位宽 8（参数可配）的同步 FIFO，采用「占用计数器」方案判断空满。本目录记录一次完整的手撕练习：从带 bug 的初版，到定位死锁根因、统一读写判据后的修正版。

## 文件清单

| 文件 | 说明 |
|------|------|
| `sync_fifo.v` | 手撕练习原版。含 2 个功能 bug 与 1 处死代码，**保留作复盘素材**，勿直接例化 |
| `sync_fifo_new.v` | 修正版。`w_en`/`r_en` 统一判据，为推荐参考实现 |

## 接口与参数

| 信号 | 方向 | 位宽 | 说明 |
|------|------|------|------|
| `i_sys_clk` | in | 1 | 系统时钟 |
| `i_sys_rst_n` | in | 1 | 低有效异步复位 |
| `i_wren` / `i_rden` | in | 1 | 写 / 读请求 |
| `i_wdata` | in | `DATA_WIDTH` | 写数据 |
| `o_rdata` | out | `DATA_WIDTH` | 读数据（寄存器输出） |
| `o_full` / `o_empty` | out | 1 | 满 / 空标志 |

参数：`DATA_WIDTH = 8`，`DATA_DEPTH = 16`。指针位宽 `[$clog2(DATA_DEPTH)-1:0]`，计数位宽 `[$clog2(DATA_DEPTH):0]`。

## 设计结构

五个时序块 + 一组组合逻辑，全部围绕两根统一判据线：

```verilog
wire w_en = i_wren && !o_full;    // 真正会发生的写
wire r_en = i_rden && !o_empty;   // 真正会发生的读
```

| 块 | 判据 | 功能 |
|----|------|------|
| 写指针 | `w_en` | 本地递增 |
| 读指针 | `r_en` | 本地递增 |
| 写存储 | `w_en` | `mem_ram[r_wr_ptr] <= i_wdata`，**无复位** |
| 读数据 | `r_en` | `r_rdata <= mem_ram[r_rd_ptr]` |
| 计数器 | `w_en`/`r_en` | 三分支：`+1` / `-1` / 保持 |

空满由计数器组合产生：`o_empty = (fifo_number==0)`，`o_full = (fifo_number==DATA_DEPTH)`。

## 关键设计决策

### 1. 计数器位宽比指针多一位

指针是座位编号（0~15，4 位够用）；计数是占用个数，取值 0~16 共 17 种，必须 5 位。若计数只有 4 位，满值 16 截断成 0，与「空」编码撞车，空满标志直接失效。

### 2. 空/满时同时读写：无特例，自动坍缩

读操作采样的是时钟边沿**前**的旧状态，与同拍写入互不可见，两个请求各自独立裁决。因此所有组合收敛为六种，无需任何特判：

| 场景 | w_en | r_en | 计数 |
|------|------|------|------|
| 只写 | 1 | 0 | +1 |
| 只读 | 0 | 1 | −1 |
| 同时读写（非空非满） | 1 | 1 | 不变（一进一出） |
| 同时读写（**空**） | 1 | 0 | +1，空解除（读请求作废） |
| 同时读写（**满**） | 0 | 1 | −1，满解除（写请求作废） |
| 均无请求 | 0 | 0 | 不变 |

被挡掉一方的场景自动退化为普通「只写 / 只读」，这正是统一判据的价值：**误用安全**——上游违反协议（空时读、满时写）时优雅降级，状态不崩。

### 3. mem_ram 不复位

存储位不挂异步复位：FPGA 上整块异步复位会阻止 BRAM 推断（退化成寄存器堆），ASIC 上复位扇出也是灾难。功能上安全，因为 `o_empty` 保证空时不会发起有效读，未写入地址永远不会被读到。

## 原版 bug 复盘（面试素材）

**Bug 1：读数据用了写指针**

```verilog
r_rdata <= mem_ram[r_wr_ptr];   // 原版：应为 r_rd_ptr
```

读出的是「刚写入的数」，先进先出顺序被破坏。

**Bug 2：计数器与指针判据不一致 → 死锁 / 失步**

原版指针用门控后的 `i_wren && !o_full`，计数器却用原始 `i_wren && i_rden && !o_full && !o_empty` 特判同时读写，漏掉空/满角落：

- **空 + 同时读写**：计数卡在 0，写指针照常递增 → 数据写入但 `o_empty` 永远为 1，**永久死锁**；
- **满 + 同时读写**：计数卡在 16，读指针照常递增 → 计数与真实占用**永久失步**。

根因是同一拍内两套逻辑对「发生了什么」判断不一致。修正方案即本文的 `w_en`/`r_en`：全模块单一判据，分支数从 4 收敛到 3，边角自动正确。

**其他清理**：删除声明后未使用的 `r_fifo_number` 死代码；自写 `clogb2` 函数替换为标准 `$clog2`。

## 延伸：为什么异步 FIFO 不能用计数器方案

计数器方案依赖「写、读事件在**同一时钟边沿**被同一 always 块原子裁决」。跨时钟域后：

1. 一个寄存器只能属于一个时钟域，计数器无法被两侧同时增减；
2. 多位二进制计数器跨域采样会「撕裂」（如 `0111→1000` 四位同翻，采到垃圾值），可能误判不满导致**溢出覆盖**。

标准解法（Cummings 套路）：指针各自本地递增并转 **Gray 码**（每次只翻一位，采样要么旧值要么新值），经两级同步器过域；空在读域判（Gray 指针相等），满在写域判（高两位取反、其余位相等）。同步延迟只会带来「假空 / 假满」的**保守方向**误判，绝不丢数据、绝不读飞。

## 面试速答

- 空满判法？→ 占用计数器，0 为空、等于深度为满；计数比指针宽 1 位（满值 16 需要 5 位）
- 空时同时读写会怎样？→ 读请求作废，退化为只写；统一 `w_en`/`r_en` 判据下无特例
- mem 为什么不复位？→ 保 BRAM 推断 / 避免复位扇出；`o_empty` 保证不会读到未写地址
- 读数据用哪个指针？→ 读指针；用错写指针是本目录初版的真实 bug
- 异步 FIFO 为何换方案？→ 计数器无法跨域原子更新，多位二进制跨域采样会撕裂 → Gray 码指针 + 2FF 同步 + 分域判空满
